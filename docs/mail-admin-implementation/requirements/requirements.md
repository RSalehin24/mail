# Behavioral requirements

R01 through R22 preserve every identified risk from the reviewed source plan. [contracts.json](contracts.json) maps each requirement to its design, tests and release gates. Expected test outcomes are defined in the [acceptance catalogue](../verification/acceptance.md).

## Detailed Gap Analysis & Solutions

| # | Potential Gap | Root Cause | Built-in Solution |
| :--- | :--- | :--- | :--- |
| R01 | **Certificate expiry, stale activation, or interrupted pair installation** | Monthly checks can miss failures; renewal updates only Maddy; replacing two files separately can leave a mismatched pair after interruption | Check daily, publish complete immutable certificate generations, pin each consumer to one generation, and recover pending activation from durable state. |
| R02 | **Memory exhaustion** | On-VM builds and concurrent password hashing can exceed available RAM | Build outside the VM, benchmark peak runtime usage, bound hashing concurrency, and make any swap persistent. |
| R03 | **Setup takeover / 2FA lockout** | A fixed email does not authenticate the first visitor; Email OTP depends on working Brevo credentials | Require a private bootstrap token, verify TOTP before initialization, and issue hash-stored recovery codes. Enable Email OTP after an authenticated delivery test. |
| R04 | **Missing, inconsistent, or partly deleted accounts** | Credentials, IMAP storage, metadata, and message files are separate; deletion can remove files before the database commits | Reconcile inventories and journaled outcomes, preserve functional accounts, and require operator reconciliation for failed storage deletion without assuming remaining messages are intact. |
| R05 | **Confusion Over Dual Passwords** | IMAP uses Maddy password; SMTP uses Brevo master key | The Client Config modal clearly delineates **Incoming Password** (account pass) vs **Outgoing Password** (Brevo key). |
| R06 | **Unexpected inbound mail routing** | Cloudflare is the current MX; an indicator alone does not move delivery to Maddy | Make routing an explicit decision; use the staged cutover and rollback procedure below if direct Maddy delivery is selected. |
| R07 | **Host compromise through the dashboard** | A Docker socket mount gives the web application broad host control, including with `:ro` | Keep Docker access in a root-owned helper with a small operation allowlist; the web container receives only its restricted Unix socket. |
| R08 | **Secret loss or authentication bypass** | Encryption-key persistence, session lifecycle, and OTP replay behavior were unspecified | Persist encryption keys outside SQLite, fail closed on missing state/keys, revoke sessions, and enforce single-use OTPs and recovery codes. |
| R09 | **Undetected deployment failures** | Insecure TLS checks and happy-path-only tests can pass while security or recovery is broken | Verify trusted HTTPS and test authorization failures, replay, partial operations, renewal failure, and backup restoration. |
| R10 | **Local exposure of existing mail** | Maddy databases and messages are readable by unprivileged host users | Restrict the existing data tree and future file creation; verify denied access as `nobody` alongside normal mail delivery. |
| R11 | **Restored authentication state regains validity** | An older backup can contain revoked sessions, consumed codes, or superseded credentials | Revoke transient authentication state and replace recovery codes before reopening a restored installation; verify intended password/TOTP settings. |
| R12 | **Helper unavailable after boot/restart** | `/run` is temporary and recreating its mounted directory leaves stale container access | Create the directory before Docker startup, preserve it across helper restarts, reconnect safely, and test a full reboot. |
| R13 | **Lost authenticator or incomplete access revocation** | TOTP replacement was absent; mailbox password changes do not close existing IMAP sessions | Add verified TOTP replacement and SSH-only recovery; make password-reset/session behavior explicit. |
| R14 | **New address cannot send** | Maddy provisioning does not create or authorize a Brevo sender | Track outbound readiness separately, document sender onboarding, and verify the fixed OTP sender before enabling Email OTP. |
| R15 | **Deletion backup omits the mailbox or recent mail** | Backup age alone does not prove coverage | Verify a trusted manifest contains the current account and its stores, display the recovery cutoff, and require acknowledgment of mail newer than that cutoff. |
| R16 | **Password reset recreates removed credentials** | Maddy 0.9.5's password update can insert a missing credential | Check both inventories under the helper mutation lock; reject missing/partial accounts and stale reset requests. |
| R17 | **Old-password login completes after a password change** | Revoking sessions alone leaves pending authentication challenges usable | Atomically revoke challenges, Email OTPs, pending enrollments, and recent-auth grants alongside sessions; test concurrent verification. |
| R18 | **Operational mail breaks after cutover or deletion** | Postmaster delivery and configured alias dependencies are not covered by account counts | Verify operational recipients and enforce root-owned protected-recipient policy before deletion. |
| R19 | **Delivery readiness is inferred or attached to stale settings** | SMTP acceptance and manual receipt confirmation have no shared, versioned record | Bind test records to saved relay revisions and expose an authenticated receipt-confirmation action. |
| R20 | **Wrong or incomplete deployment starts** | Short bind syntax can create missing paths; image/schema/helper compatibility is implicit | Reject missing bind sources, use the recorded local image, and check protocol/schema versions before accepting writes. |
| R21 | **Requests or storage growth disrupt the small VM** | Blocking work, request queues, database writes, and ongoing backup/disk monitoring need explicit bounds | Bound request/work queues and deadlines, fail safely on storage errors, schedule backups, and alert independently on backup failures and low disk space. |
| R22 | **Renewal/recreation interrupts an account mutation or backup** | The legacy script bypasses locks; ACME acquisition also writes state included in backups | Pause/drain legacy renewal before the first production backup or Maddy change. Use the renewal-run lock before the maintenance lock when both are needed, exclude ACME writers from backups, and defer maintenance on unresolved outcomes. |
